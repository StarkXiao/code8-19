# 古树名木复壮跟踪系统

按株建立古树名木档案，记录**体检结论**与**复壮措施**，并在复壮完成后**连续跟踪两年内存活情况**。

零外部运行时依赖：Node.js 内置 HTTP 服务 + JSON 文件存储 + 原生前端（无构建步骤），`npm start` 即用。

---

## 业务闭环

```
新建立档（自动编号 GS-年份-序号，记录树种/等级/树龄/位置/树体指标/责任人）
   ↓
树体体检（生长势：旺盛/正常/衰弱/濒危/死亡；问题项多选；诊断结论与建议）
   ↓
登记复壮措施（类型多选、工期、施工单位、费用、状态）
   ↓ 全部措施完成并填写实际完成日期
启动两年跟踪（以最后一项措施完成日为基线，自动生成 3/6/9/12/18/24 月六个节点）
   ↓
逐节点填报：存活情况 + 生长势 + 新问题 + 现场处置；计划外可随时记"临时随访"
   ├── 任一节点确认死亡 ──→ 自动结案：复壮失败
   └── 24 个月（延长观察则 36 个月）全部存活 ──→ 评定结案：复壮成功
```

仪表盘统计在册数量、各状态分布、**逾期未填节点**（自动按当天日期推算并标红）、复壮成功率；
待办按到期日排序，到期未填自动逾期。

## 快速开始

要求 Node.js ≥ 18。

```bash
npm start          # 默认 http://localhost:3000
npm run seed:force # 写入 5 株演示数据（正常养护/复壮中/跟踪逾期/成功/失败各一）
npm test           # 20 个测试（领域规则 15 + 真实 DOM 前端冒烟 5）
```

环境变量（均有默认值，可省略）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务端口 |
| `DB_FILE` | `data/db.json` | JSON 数据库路径（相对项目根） |
| `TRACKER_TODAY` | 系统当天 | 固定"今天"的日期，用于演示逾期推算，如 `2026-10-01` |

## 页面与接口

**页面**（hash 路由，无需前端构建）

- `#/dashboard`：指标卡、状态分布、待办（逾期置顶）
- `#/trees`：档案列表，关键字搜索（编号/树种/拉丁名/位置/单位/责任人）+ 状态过滤
- `#/trees/:id`：一树一档详情——基础信息、体检时间线、措施卡片、跟踪节点条与记录；
  可直接打印（`🖨 打印档案`，打印版含体检/措施/跟踪三张表与签字栏）

**接口**（均为 JSON，写操作服务端校验）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/constants` | 枚举字典与当天日期 |
| GET | `/api/stats` | 仪表盘统计与待办 |
| GET/POST | `/api/trees` | 列表（`q`/`status`）/ 新建立档 |
| GET/PATCH | `/api/trees/:id` | 详情（含推导视图）/ 编辑 |
| POST | `/api/trees/:id/exams` | 新增体检结论 |
| POST | `/api/trees/:id/measures` | 登记复壮措施 |
| PATCH | `/api/measures/:id` | 修改措施（含标记完成） |
| POST | `/api/trees/:id/followup/start` | 启动两年跟踪 |
| POST | `/api/trackings/:id/records` | 填报节点 / 临时随访 |
| PATCH | `/api/followup-records/:id` | 修改跟踪记录 |
| POST | `/api/trackings/:id/extend` | 延长观察（加挂 30/36 月，仅一次） |
| POST | `/api/trackings/:id/finalize` | 评定结案 |

## 关键业务规则（均在服务端强校验，有测试覆盖）

- **档案编号**按年份自增 `GS-YYYY-NNN`；树种、等级、树龄、位置为必填，经纬度/树高/胸径/冠幅校验数值范围。
- **跟踪启动闸门**：没有措施不能启动；必须全部"已完成"且每项都有实际完成日期；基线日自动取最晚完成日；每株只能启动一次。
- **节点不可重复填报**（同一月份），重复请修改原记录；跟踪日期不得早于基线日。
- **死亡即自动失败结案**（`alive=false` 或生长势为"死亡"），结案后记录冻结，不能再填报或修改。
- **成功结案闸门**：计划节点（含延长后的 30/36 月）全部有存活记录，缺一不可，错误信息列出缺失节点。
- **延长观察**最多一次，加挂第 30、36 月节点。
- **逾期**：节点应到日期（基线 + N 个月，月末日期自动取当月最后一天）早于当天且未填报，即按逾期天数标红并进入待办。

## 结构

```
ancient-tree-tracker/
├─ src/
│  ├─ domain.mjs     枚举/校验/状态推导/跟踪计划（纯函数，核心规则唯一来源）
│  ├─ db.mjs         JSON 持久化（原子写、写串行化）
│  └─ server.mjs     HTTP 服务 + 路由 + 静态托管
├─ public/
│  ├─ index.html
│  ├─ styles.css
│  └─ app.js         hash 路由、仪表盘/列表/详情、通用表单弹窗
├─ scripts/reset-db.mjs   演示数据
├─ test/
│  ├─ domain.test.mjs     领域规则（15 个用例）
│  └─ ui.smoke.test.mjs   happy-dom 真实 DOM 端到端冒烟（5 个用例）
└─ data/db.json       运行时数据
```

## 说明与边界

- 单机 JSON 存储面向单部门、少量档案（数千株内）的日常管理；多用户并发与权限体系未包含，
  如需多人协作可把 `src/db.mjs` 换成 SQLite/PostgreSQL 实现，领域层不用改。
- 日期按 UTC 归一化处理，节点对日规则：基线日为月末时（如 1/31 + 1 月）取目标月最后一天（2/28、闰年 2/29）。
